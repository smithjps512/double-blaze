# Day 24: v2 change requests as level stories

No em dashes anywhere in this document or any copy it generates.

At the end of today, every starred change is written as a new or changed level story with checks and scenarios, and v2 is turned in.

## Again (5 minutes)

1. Read your starred musts and shoulds out loud, in order.

## Watch (5 to 10 minutes)

The teacher does this on the projector, start to finish. Nobody types until it
is done.

1. **Open** Demo Studio's Levels tab. Take a must: "players fall through the
   floor after the crane". Show it is already a bad day from yesterday.
2. **Change** the level's checks so they would catch it: "The floor after the
   crane has no gaps."
3. **Take** a should that is a new idea: "a practice room before level 1".
   Write it as a new level story with checks, a happy path and a bad day.
4. **Say**: a change request is not "please fix it". It is a story, a check,
   or a scenario. Double Blaze builds v2 from the doc again.

Say out loud: you do not ask for a change. You write it, so it can be built and checked.

## Do (25 to 30 minutes)

1. *(again)* Your starred list is in front of you. Every bug is already a bad
   day.
2. **(today)** Each must: change the level's story, checks or scenarios so the
   doc says exactly what should happen.
3. **(today)** Each should: a new level story, or a change to an existing one,
   with checks and scenarios.
4. **(today)** Open Level up. Every level green again.
5. **(today)** Read the Design doc tab out loud. The Producer tells the
   teacher: "v2 is ready."

Stuck? Every change answers: what should the player see, and how would we check it?

## Done when

Every starred change is in the design doc, every level is green, and the Producer has told the teacher v2 is ready.

Run `npm run studio:export` again and build v2 for each studio. Builds go on
[/play](https://doubleblaze.solutions/play) by day 26.
